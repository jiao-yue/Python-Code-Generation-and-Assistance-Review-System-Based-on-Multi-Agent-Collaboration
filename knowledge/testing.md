# pytest 测试设计与覆盖

## 用例结构

- 一个用例只验证一个行为，用例名写清场景与预期，例如 `test_average_empty_returns_zero`。
- 用例体保持“准备 → 执行 → 断言”三段，避免在断言里再做业务计算。
- 测试函数以 `test_` 开头，测试文件以 `test_` 开头，确保 pytest 能收集。
- 被测模块通过 `from solution import 函数名` 导入，不复制实现代码到测试里。

## 边界覆盖清单

- 正常输入：典型值、单元素、多元素。
- 空输入：空列表、空字符串、空字典。
- 缺失输入：`None`、缺省参数、可选参数未传。
- 非法输入：类型错误、格式错误、超范围数值、超长字符串。
- 数值边界：零、负数、最大值、除数为零。
- 序列边界：首元素、末元素、越界索引、单元素集合。

## 断言质量

- 断言具体值，不断言“不是 None”这类弱条件。
- 断言要能区分错误实现：断言 `== 2` 而不是 `> 0`。
- 异常场景用 `pytest.raises(具体异常类型)`，并校验异常信息关键片段。
- 浮点结果用 `pytest.approx` 比较，避免精度导致的偶发失败。

## 测试隔离与确定性

- 用例之间互不依赖执行顺序，每个用例自建数据。
- 不访问网络、不读写固定绝对路径、不依赖当前时间。
- 需要临时文件时用 `tmp_path`，用完自动清理。
- 随机数据固定种子，或直接用写死的样本。
- 不 mock 被测函数本身，否则测不到真实逻辑。

## 参数化与可维护性

- 同一逻辑的多组输入用 `@pytest.mark.parametrize` 展开，避免复制粘贴用例。
- 期望值与输入放在一起，让失败信息自带上下文。
- 测试代码同样遵守命名与格式规范，保持可读。
- 修复缺陷时先补一个能复现缺陷的用例，再改实现。
