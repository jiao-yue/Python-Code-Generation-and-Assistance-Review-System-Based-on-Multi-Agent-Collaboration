# 安全评审案例：输入、注入与输出

> 参考来源：OWASP Cheat Sheet Series
> https://github.com/OWASP/CheatSheetSeries
> 说明：以下条目从输入校验、SQL 注入、命令注入、日志与依赖五个场景整理，用于安全审核。

## 输入校验：先解析再校验

- 同时校验语法（类型、格式、长度、范围）与语义（业务上是否合理）。
- 白名单优于黑名单：定义允许的取值集合，拒绝集合之外的值，而不是枚举恶意字符串。
- 在缓冲或解析之前限制请求大小，并限制嵌套深度；解析失败必须明确拒绝。
- 不要把“转成整数”当成校验：类型正确不代表数量在允许范围内。
- 客户端校验只能用于即时提示，服务端必须再做一次校验；内部服务传来的数据同样不可信。
- 校验失败后不要继续使用部分校验的数据，避免半合法状态进入业务逻辑。

## SQL 注入：参数化查询

- SQL 结构与数据值必须分离：所有动态值通过参数绑定，禁止字符串拼接用户输入。
- 表名、列名、排序方向不能参数化时，把用户选择映射到固定的白名单值。
- 输入校验不能替代参数化查询；手工转义在不同数据库方言下都不可靠。
- ORM 的原生查询语言同样存在注入风险，动态条件也要使用参数绑定。
- 存储过程内部拼接的动态 SQL 也要参数化，调用处绑定参数并不能保护过程内部。
- 数据库账号使用最小权限，应用账号不要授予管理员权限。

## 命令与路径注入

- 调用外部命令时使用 `subprocess.run([...], shell=False)`，以列表传参，禁止拼接用户输入。
- `os.system`、`os.popen`、`shell=True` 搭配外部输入视为命令注入。
- 文件路径先取 `basename` 剥离目录部分，防止 `../` 目录穿越。
- 解析后的绝对路径必须校验仍位于允许的根目录内，再执行读写。
- 文件上传不信任文件名与 Content-Type，应限制大小、类型并在隔离目录中保存。

## 输出编码与日志安全

- 按输出上下文选择编码：HTML、JSON、SQL、日志各有不同的转义规则，不能共用一套。
- 日志不记录完整凭证、完整请求体或内部路径；只记录必要的失败原因与元数据。
- 保留在日志中的不可信值要按日志格式转义，防止日志注入与伪造日志行。
- 面向用户的错误提示不要回传 traceback、SQL 语句或服务器内部细节。
- 比较口令与令牌使用 `hmac.compare_digest`，避免计时攻击。

## 依赖、配置与权限

- 依赖固定版本并定期审计，不引入来源不明或长期未维护的包。
- 密钥、令牌、数据库口令从环境变量或密钥管理服务读取，不写进源码与配置样本。
- 关闭调试模式与详细错误页，生产环境不暴露堆栈与依赖版本。
- 数据库、对象存储、消息队列都使用最小权限账号，并限制网络可达范围。
- 安全随机数使用 `secrets`，不要用 `random`；口令与签名使用 `sha256` 及以上算法。
