# Python 安全审查要点

## 危险代码执行

- `eval`、`exec`、`compile` 直接执行字符串，等于把任意代码执行权交给输入方，属阻断级问题。
- 需要按名字分发行为时，用显式的字典映射到函数对象，不要拼字符串再执行。
- `__import__`、`importlib` 动态导入用户可控模块名，同样存在代码注入风险。
- 模板渲染若允许用户控制模板源码（如未沙箱化的 Jinja2），也可能导致代码执行。

## 命令与路径注入

- `os.system`、`os.popen` 拼接外部输入会被 shell 解释，应改用 `subprocess.run([...], shell=False)` 并以列表传参。
- 使用 `shell=True` 且命令含用户输入时，必须视为命令注入。
- 拼接文件路径前用 `os.path.basename` 或 `Path(...).name` 剥离目录部分，防止 `../` 目录穿越。
- 打开用户指定路径时限制在固定根目录内，解析后校验绝对路径仍位于该根目录。

## 反序列化与数据加载

- `pickle.loads`、`pickle.load`、`marshal.loads` 反序列化不可信数据可执行任意代码，应改用 JSON。
- `yaml.load` 必须换成 `yaml.safe_load`，否则可构造任意对象。
- 不信任 HTTP 响应、文件内容、缓存值的结构，解析前校验类型与字段。

## 敏感信息与异常泄露

- API Key、数据库口令、令牌不得硬编码在源码中，应从环境变量或配置读取。
- 日志与异常信息不得输出完整凭证、完整请求头或内部路径。
- 面向用户的错误提示不要直接返回 traceback 或 SQL 语句，内部细节写入日志即可。
- 比较口令或令牌使用 `hmac.compare_digest`，避免计时攻击。

## 加密与随机

- 不使用 `md5`、`sha1` 做安全用途（口令、签名），改用 `sha256` 及以上或专用口令哈希。
- 安全场景的随机数必须用 `secrets`，不能用 `random`。
- 不在代码中写死加密密钥与初始向量。

## 网络与资源

- 所有外部 HTTP 请求必须设置超时，避免线程被无限挂起。
- 响应的体积要有上限，避免被超大响应拖垮内存。
- 用户可控的 URL 需校验协议与目标主机，防止服务端请求伪造（SSRF）。
