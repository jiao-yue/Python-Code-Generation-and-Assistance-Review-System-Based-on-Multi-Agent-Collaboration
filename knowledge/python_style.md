# Python 规范与可读性

## 命名规范

- 函数与变量使用 snake_case，类使用 PascalCase，常量使用全大写 UPPER_CASE。
- 名字要表达意图：`average_of_numbers` 优于 `calc`，`retry_count` 优于 `n`。
- 布尔变量用 `is_`、`has_`、`can_` 前缀，避免 `flag` 这类无信息量的命名。
- 不用单字母命名，循环下标 `i`、`j` 除外；不使用与内置名冲突的名字（`list`、`dict`、`str`、`id`、`input`）。
- 私有辅助函数以下划线开头，避免对外暴露实现细节。

## 格式与行宽

- 缩进统一 4 个空格，不使用 Tab。
- 单行不超过 79 字符（本项目按 100 字符执行），超长表达式应换行而不是压成一行。
- 顶层函数与类之间空两行，类内方法之间空一行。
- 运算符两侧、逗号之后各留一个空格；不在括号内侧留空格。
- 导入分三组：标准库、第三方库、本项目模块，组间空一行；避免通配符导入 `from x import *`。

## 注释与文档字符串

- 注释解释“为什么这样做”，不要复述代码“做了什么”。
- 公开函数写 docstring，说明参数含义、返回值、可能抛出的异常。
- 注释与代码同步维护，过期注释比没有注释更危险。
- 不保留被注释掉的死代码，交给版本控制管理历史。

## 可读性

- 避免魔法数字与魔法字符串，提取为具名常量。
- 单个函数只做一件事；超过约 40 行或嵌套超过 3 层时考虑拆分。
- 优先早返回（guard clause）减少 `else` 嵌套，让主流程保持在最左层。
- 用 `enumerate` 代替手工维护下标，用 `zip` 代替并行下标访问。
- 推导式保持单层，多层嵌套推导式应改为显式循环。

## 类型注解

- 公开函数标注参数与返回类型，容器标注元素类型（`list[str]`、`dict[str, int]`）。
- 可选值用 `X | None`，不要用可变对象作为默认参数。
- 注解用于表达契约，不用来替代运行时校验；外部输入仍需校验。
