# 项目使用手册

本文面向首次使用本项目的人员，介绍从安装启动到生成代码、审核代码、使用附件、管理会话和导出结果的完整操作方法。示例命令以 Windows PowerShell 为主，默认项目地址为 `http://127.0.0.1:8000/`。

## 一、系统能做什么

系统提供两种工作模式：

| 模式 | 适用场景 | 系统执行内容 |
| --- | --- | --- |
| 代码生成 | 根据自然语言或需求附件生成新代码 | 需求确认、按需澄清、代码生成、审核、测试、失败修复、结果导出 |
| 只审核代码 | 检查已有 Python 代码，不重新生成 | 静态分析、模型审核、可选 pytest 测试、评分与修改建议 |

代码生成支持 Python、Java、C、HTML/CSS/JavaScript，可生成单函数或 2～12 个文件的小型项目。生成失败或测试未通过时，系统会尝试定向修复；超过最大修复轮次后保留当前最优版本。

## 二、首次安装与启动

### 2.1 准备环境

必需环境：

1. Python 3.13；
2. MySQL 8.x，并确保 MySQL 服务已启动；
3. 一个可用的大模型服务：DeepSeek、火山方舟或本机 Ollama。暂时没有模型服务时可使用离线 Mock 演示。

按生成语言准备可选工具：

| 生成内容 | 额外工具 | 用途 |
| --- | --- | --- |
| Python | pytest 已随项目依赖安装 | 执行生成测试 |
| HTML/CSS/JavaScript | Node.js | 对生成的 JavaScript 做语法检查；浏览器用于实际打开网页 |
| Java | JDK，并确保 `javac` 可用 | 编译和运行 Java 项目 |
| C | GCC/MinGW，并确保 `gcc` 可用 | 编译链接和运行 C 项目 |

缺少 Java/C 工具不会阻止系统启动，但对应语言的检查会报告工具不可用。

### 2.2 安装项目依赖

在项目根目录打开 PowerShell：

```powershell
cd "项目根目录"
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

如果本机使用 `uv`，也可以执行：

```powershell
uv pip install -r requirements.txt
```

`.env` 保存真实密钥和数据库口令，不要提交到 Git，也不要发送给他人。

### 2.3 配置数据库

`.env` 中按实际情况填写：

```env
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=你的数据库口令
DB_NAME=graduation project
```

系统启动时会自动创建数据库及所需数据表，无需手动执行建表 SQL。数据库账号需要具备创建数据库、创建表和增删改查权限。

### 2.4 选择模型

#### 方案 A：使用 DeepSeek

```env
DEEPSEEK_API_KEY=你的DeepSeek密钥
DEEPSEEK_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-chat
```

未显式设置 `LLM_PROVIDER` 时，默认使用 DeepSeek。

#### 方案 B：使用本机 Ollama

先启动 Ollama，并确认模型名称：

```powershell
ollama list
```

在 `.env` 中设置：

```env
LLM_PROVIDER=ollama
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen3.5:4b
OLLAMA_TIMEOUT=600
OLLAMA_THINK=0
REVIEW_PARALLEL=0
```

`OLLAMA_MODEL` 必须与 `ollama list` 中的名称完全一致，地址不要添加 `/v1`。本机 Ollama 不需要 API Key。`REVIEW_PARALLEL=0` 可减少本地多路审查同时排队造成的等待；云端模型可保持默认并行审查。

#### 方案 C：离线 Mock 演示

```env
FORCE_MOCK=1
```

Mock 不访问真实模型，适合演示流程和排查环境问题，但生成结果不能用于证明真实模型质量或作为论文实验数据。

修改 `.env` 后需要重启后端服务才能生效。

### 2.5 启动并检查

```powershell
python -m uvicorn api.server:app --host 127.0.0.1 --port 8000
```

看到服务启动信息后，用浏览器打开：

```text
http://127.0.0.1:8000/
```

健康检查地址：

```text
http://127.0.0.1:8000/api/health
```

重点检查：

| 字段 | 正常含义 |
| --- | --- |
| `status=ok` | 后端服务正常 |
| `provider` | 当前模型提供方，如 `deepseek`、`ollama` |
| `mode=api` | 正在调用云端模型 |
| `mode=local` | 正在调用本地模型 |
| `mode=mock` | 正在使用离线兜底 |
| `memory=mysql` | 会话使用 MySQL 持久化 |
| `rag.chunks` | 当前知识库片段数量，内置基线为 41，导入资料后可能增加 |

左下角状态栏也会显示当前模型与连接状态。

## 三、代码生成的使用方法

### 3.1 基本操作

1. 点击左侧“新建对话”；
2. 选择“代码生成”；
3. 在底部输入框描述需求；
4. 点击“发送”；
5. 等待页面依次显示需求确认、生成、审核、测试等阶段；
6. 完成后查看代码、运行命令、审核问题、评分卡和测试结果；
7. 需要保存时点击“导出结果 ZIP”。

生成过程中不要重复点击发送。阶段流式返回期间，完整代码与报告会在最终结果到达后统一展示。

### 3.2 如何写清楚需求

建议至少写明：语言、功能名称、输入、输出、边界情况和期望文件。

Python 单函数示例：

```text
写一个 Python 函数 square(n)，接收 int 或 float，返回 n 的平方；
非数字输入抛出 TypeError，并生成 pytest 测试。
```

HTML 多文件示例：

```text
用原生 HTML、CSS、JavaScript 生成一个静态购物网页，直接生成
index.html、styles.css、app.js 和 README.md。包含 4 个商品、商品名称搜索、
加入购物车按钮和购物车数量；不使用后端，不引用外部图片或框架。
```

Java 项目示例：

```text
用 Java 生成一个控制台学生管理系统，包含学生增删改查、按学号查询、
README 和运行命令；程序入口为 Main，数据先保存在内存中。
```

需求越明确，模型越不需要自行假设。文件较多时应控制范围，避免一次要求完整商业系统或大量页面。

### 3.3 回答需求澄清

如果关键歧义会改变实现结果，页面会显示“需求需要确认”问答卡：

1. 在问题下方填写答案，至少回答一条；
2. 点击“提交回答并继续”；
3. 系统从中断位置恢复，不需要重新创建会话或重复原始需求。

问答卡尚未提交时，底部输入框不会替代回答入口。若模型已能采用合理默认，也可能不提问而直接生成，这是正常行为。

### 3.4 查看结果与运行生成项目

结果中重点关注：

| 内容 | 说明 |
| --- | --- |
| `COMPLETED` | 当前链路完成，质量门禁与项目检查通过 |
| `BEST_EFFORT` | 已达到修复轮次上限，保留当前最优版本，仍有问题需要人工处理 |
| 入口文件与运行命令 | 在生成目录中启动项目的依据 |
| 审核问题与评分卡 | 查看规范、安全、逻辑、边界和测试建议 |
| pytest/编译/静态检查 | 判断代码是否实际执行或通过静态验证 |
| 各轮版本 | 对比初始生成与修复后的版本 |

运行期文件位于：

```text
storage/generated/chat_<run_id>/
```

运行前先阅读生成项目的 `README.md` 和结果中的 `run_command`。例如：

```powershell
# Python：进入生成目录后运行测试
cd "storage/generated/chat_<run_id>"
python -m pytest -q

# HTML：保持 HTML/CSS/JS 文件在同一目录，可启动临时静态服务
python -m http.server 8080 --bind 127.0.0.1
# 然后访问 http://127.0.0.1:8080/index.html
```

Java/C 项目使用结果给出的 `javac`、`java` 或 `gcc` 命令，并确保对应工具已安装。

## 四、只审核已有代码

1. 点击左侧“只审核代码”；切换模式会新建对应模式的会话；
2. 将 Python 代码粘贴到底部主输入框，或添加 `.py`、文本、文档等代码附件；
3. 如需执行测试，展开“添加测试代码（可选，用于运行 pytest）”，粘贴 `test_*.py` 内容；
4. 点击“发送”；
5. 查看审核问题、评分卡和 pytest 结果。

仅审核模式不会生成或改写用户代码。不附测试时仍可完成静态与模型审核，不会因为测试数量为 0 自动判定失败；附测试后，测试失败会成为需要处理的问题。

## 五、附件与知识库的使用

### 5.1 两种上传入口

| 按钮 | 用途 | 是否进入长期 RAG 索引 |
| --- | --- | --- |
| 添加附件 | 为当前生成或审核提供材料 | 否 |
| 导入知识库 | 将规范、需求或案例作为后续检索资料 | 是 |

操作步骤：

1. 点击对应按钮并选择文件；
2. 等待解析完成，检查附件列表中的文件名、复用状态、警告或“已入库”标记；
3. 发送前可移除不需要的附件；
4. 在输入框补充具体任务，例如“根据附件中的需求生成 Python 函数”，然后发送。

只上传附件而不输入文字也可以发起任务，但补充一句明确目标通常更容易得到符合预期的结果。

### 5.2 支持格式与限制

- Word：`.docx`，旧版 `.doc` 不支持；
- Excel：`.xlsx`、`.xls`；
- PDF：`.pdf`，文字过少的扫描页会尝试本地 OCR；
- 图片：`.png`、`.jpg`、`.jpeg`、`.bmp`、`.webp`、`.tif`、`.tiff`，进行本地 OCR；
- 文本/代码：`.txt`、`.py`、`.md`、`.csv`、`.json`、`.log`。

默认单次最多 5 个文件，单文件最大 20 MB。图片和扫描 PDF 只承诺文字识别，不进行通用图像语义理解。相同字节内容会按 MD5 去重复用，即使文件名不同也不会重复解析或重复建立知识条目。

“导入知识库”应只用于确实需要长期检索的资料；普通一次性需求文件使用“添加附件”即可。

## 六、历史会话管理

- **新建对话**：点击“新建对话”，空会话也会立即保存；
- **继续历史对话**：点击左侧历史项，系统读取该会话的消息与结果；
- **重命名**：将鼠标移到历史项上，点击重命名按钮，输入新标题后按 Enter；Esc 取消，输入框失焦也会保存；
- **删除**：点击历史项的删除按钮并确认。删除会同步删除 MySQL 中该会话及其消息，操作前请确认不再需要；
- **模式隔离**：代码生成与只审核使用不同会话，切换模式时会新建会话，不会把两种任务混入同一结果。

刷新或重新打开浏览器不会清空已保存会话。

## 七、导出结果

完成一次生成或审核后，在结果区域点击“导出结果 ZIP”。前端导出当前会话最近一次完整结果，包含需求、最终文件、审核报告、测试结果和 `manifest.json`；多轮生成还包含各轮版本。

也可使用接口：

```http
GET /api/conversations/{conversation_id}/export?format=zip&scope=latest
GET /api/conversations/{conversation_id}/export?format=zip&scope=all
```

- `latest`：最近一次完整结果；
- `all`：该会话的全部完整结果；
- 导出只读取已保存结果，不重新调用模型；
- 默认 ZIP 上限为 20 MB，可通过 `EXPORT_MAX_BYTES` 调整。

## 八、常见问题与处理方法

### 8.1 页面打不开或一直显示连接中

1. 确认启动命令仍在运行，且端口为 8000；
2. 访问 `http://127.0.0.1:8000/api/health`；
3. 检查是否有其他程序占用 8000 端口；
4. 若页面能打开但样式异常，使用浏览器强制刷新。

### 8.2 健康检查显示 `mode=mock`

这表示当前没有使用真实模型。检查：

- 是否误设了 `FORCE_MOCK=1`；
- DeepSeek/火山方舟密钥是否填写；
- `LLM_PROVIDER` 是否符合预期；
- 修改 `.env` 后是否重启服务。

### 8.3 Ollama 调用失败或响应很慢

1. 执行 `ollama list`，确认模型已下载且名称与 `.env` 一致；
2. 确认 `http://127.0.0.1:11434` 对应的本机 Ollama 服务可用；
3. 保持 `OLLAMA_BASE_URL` 为服务根地址，不带 `/v1`；
4. 本地单卡建议设置 `REVIEW_PARALLEL=0`；
5. 输出为空或截断时检查 `OLLAMA_MAX_TOKENS=8192`、`OLLAMA_NUM_CTX=16384` 和超时配置；
6. 简单任务可保持 `OLLAMA_THINK=0`，复杂任务可尝试开启推理或更换更大模型。

小模型生成错误代码或错误测试并进入 `BEST_EFFORT`，不一定代表 Ollama 接口故障，应同时查看具体审核与测试错误。

### 8.4 长时间无结果、JSON 解析失败或重试耗尽

可能原因包括模型服务限流、网络超时、需求过大或输出被截断。可按顺序处理：

1. 缩小单次需求范围，将大型项目拆成多个小任务；
2. 检查模型服务状态、额度和网络；
3. 云端模型检查 `LLM_TIMEOUT`、`LLM_MAX_TOKENS`，本地模型检查对应 Ollama 配置；
4. 稍后重新发送；若已有失败结果，先根据错误信息调整需求，不要盲目连续重试。

### 8.5 网页生成后样式或脚本没有生效

确保 `index.html`、CSS 和 JavaScript 文件位于同一套生成目录中，且 HTML 引用路径没有被单独移动。建议通过临时 HTTP 服务访问，而不是只复制 HTML 文件到其他位置。

### 8.6 Java/C 检查提示工具不可用

安装 JDK 或 GCC/MinGW，并确认新的终端中 `javac -version`、`gcc --version` 可执行。安装后重启后端服务，使其读取更新后的 PATH。

### 8.7 附件上传失败或没有使用附件内容

检查文件格式、数量、大小和解析警告；旧版 `.doc` 请先另存为 `.docx`。扫描件应尽量清晰。若使用知识库资料，必须点击“导入知识库”，普通“添加附件”不会进入长期索引。

## 九、运行自检

修改代码或部署到新环境后，可在项目根目录执行：

```powershell
python -m pytest -q
python -m ruff check .
python -m compileall -q api config graph models prompts services scripts evaluation
node --check web/app.js
```

当前全量单元测试为 77 项。测试结束会清理 `test_` 前缀的测试数据；也可手动执行：

```powershell
python -m scripts.cleanup_test_data
```

该清理命令只用于测试数据，不要在不了解影响时把它当作普通会话维护工具。真实全链路验证记录见 [`full-chain-validation.md`](full-chain-validation.md)。

## 十、推荐使用流程

首次使用建议按以下顺序操作：

1. 用离线 Mock 或一个简单 Python 函数确认安装和页面流程；
2. 检查 `/api/health`，确认实际使用的模型与 MySQL；
3. 使用明确的小需求完成第一次真实生成；
4. 查看审核、测试和运行命令，并在生成目录中实际运行；
5. 再尝试多文件网页、Java/C 项目或附件需求；
6. 对重要结果及时导出 ZIP；
7. 复杂任务优先拆分，小模型优先验证简单场景，不把 `BEST_EFFORT` 结果直接当作可交付成品。
